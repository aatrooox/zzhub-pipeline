# 写稿 Brief 构建指南

当 `next_action.action` 为 `attach-body` 且 `params.spawn` 为 `true` 时，主 Agent 需要构建写作 Brief 并 spawn sub-agent 完成写作。

## 工作模式

从 `next_action.params.worker_mode` 读取：

- **write**：从零写一篇新文章。任务中的 `intent_text` 描述了用户想要的内容。
- **write-from-materials**：`source_materials_path` 有上游素材。先读完再写。
- **research-then-write** / **research-then-write-from-materials**：先调研再写稿。用网络搜索收集事实信息，然后动笔。

## 构建写作 Brief

主 Agent 根据 `intent_text`、`worker_mode` 和用户原始需求构建写作 Brief，包含：

- 文章主题、目标读者、字数要求
- 需要覆盖的核心要点和角度
- 语气和风格要求（见下方质量要求）
- Markdown 格式规范（见下方格式要求）
- **标题要求**：标题占整篇文章 60% 的权重，必须反复打磨。好标题的标准：有悬念、有冲突感、让人产生"这说的是什么？"的好奇心、读完标题就想点进来
- **标题关键词**：产出标题的同时，从标题中挑选 1-2 个关键词（必须是标题中实际出现的词），用于生成文字封面图时高亮显示。选择标准：最有冲击力、最能概括文章核心、读者一眼就能被吸引的词。例如标题"那天晚上我用 AI 发了第一篇文章"中，关键词可选"AI"或"第一篇文章"

## Spawn Sub-agent

使用 `Agent` 工具 spawn sub-agent（类型选择 `general-purpose`），prompt 中只包含写作 Brief 和格式规范。**不要把主对话中的无关上下文、CLI 输出、状态机细节带入 sub-agent。** Sub-agent 只需要知道"写什么"和"怎么写"，不需要知道 zzhub-pipeline 的存在。

## 交稿流程

Sub-agent 完成写作后返回正文。主 Agent 检查正文是否符合格式要求（有无 `##` 标题、段落是否简短等），同时**从正文末尾提取封面高亮关键词**（去掉 `**封面高亮关键词**: ` 标记后得到逗号分隔的关键词列表）。然后通过以下命令交稿：

```bash
zzhub-pipeline attach-body --state {state_path} --body-text "{正文内容（去掉关键词行的纯净正文）}"
```

如果正文很长，先写到临时文件，然后用 `--body {file_path}` 代替。

**重要：** 后续执行 `prepare` 时，必须把提取到的关键词通过 `--highlight-words` 传入，这样 render 生成文字封面图时才会高亮这些词：

```bash
zzhub-pipeline prepare --state {state_path} --highlight-words "关键词1,关键词2"
```

如果 sub-agent 没有输出关键词或关键词格式异常，prepare 时会自动从标题中提取（fallback 行为），但人工选的关键词通常效果更好。

## 写稿格式要求

**必须在 sub-agent prompt 中明确给出：**

- 使用 `## 章节名` 二级标题划分章节（公众号正文不用 `#` 一级标题）
- 使用 `**粗体**` 强调关键词、关键数据、重点句
- 使用 `- ` 或 `1. ` 组织列表和要点
- 使用 `>` 引用重要内容或金句
- 段落简短，适合手机阅读（每段 2-4 句）
- 章节之间用空行分隔，适当使用分割线

## 写稿质量要求

**必须在 sub-agent prompt 中明确给出：**

### 一、标题（占 60% 权重）

- 花最多时间打磨标题，至少尝试 5 种以上角度再定稿。
- 好标题的特征（至少命中 2 项）：
  - **悬念**：让人产生"这说的是什么？"的好奇心（例：《停止继续探索 OpenClaw，回到打磨 SKILL 上来》）
  - **冲突**：有对立面或张力（例：《稳定是最大的牢笼》）
  - **反差**：打破常识预期（例：《30 岁前端开发离失业还有几年》）
  - **具体数字**：精确数据比模糊描述更抓人（例：《一个月内写了 16w+ 行代码》）
- 避免：平淡陈述句、官方通稿式、教科书式。

### 二、风格（作者个人特征）

- **开头**：一个具体场景或精确数据直接切入，不铺垫。例：《从大学毕业到现在，已经第九年了》《周六回了老家》。
- **叙事**：场景还原能力强——对话直接引语、动作细节、感官描写。然后从具体突然跳到抽象感慨。
- **语言**：口语化自言自语（"还挺高级嘞""没糖那个是真难喝"）；括号补充内心 OS（"(放心吧老板,已经给您备注好了)"）；技术词保持英文不翻译（OpenClaw、Skill、Agent、Token）；数据精确到小数点（288.66 元、47844 行代码）。
- **结构**：一篇里生活/技术/情绪自然混写，不割裂；可以突然转弯从具体跳到抽象。
- **价值观**：直给不绕，对割韭菜等行为不藏着批评。
- **结尾**：自然停下，不追求"总结三点"式收尾，偶尔一句感慨收束但不升华。

### 三、写作手法（借鉴名家技巧）

- **余华式细节**：用克制、冷静的笔触写日常场景，让情感从细节里自然渗出来，不直接煽情。例：写亲情不是"我很感动"，而是"他摆了摆手，冲我嘿嘿一笑，风一样的速度就骑走了"。
- **刘震云式绕**：把一个道理用反复、递进、自我否定的方式说出来，形成节奏感。例："你以为的 A 其实是 B，而 B 背后还有一个 C。"
- **场景切片**：不写"我这一周很累"，写"孩子偷喝柠檬水、姥爷骑车、帐篷里躺着"——用 3 个具体场景让读者自己感受到累。
- **突然转弯**：叙事进行到一半突然跳到抽象思考，制造认知冲击。例：从孩子偷喝饮料 → "生孩子好不好这种问题让中年人像走马灯"。

### 四、互联网传播（流量特征）

- **前 3 句定生死**：开头必须让读者在 3 秒内决定是否继续看。用场景、数据或悬念钩住。
- **每段都要有钩子**：每一段结尾留一个让人想继续往下读的钩子（悬念、转折、反问、未解之谜）。
- **冲突前置**：有争议、有对立面、有张力。不是平铺直叙"我做了什么"，而是"我做了什么 vs 常规认知是什么"。
- **反差制造记忆点**：打破读者预期。例：以为在写技术 → 突然聊到人生；以为在聊日常 → 突然给出深刻洞察。
- **金句密度**：每 300-500 字至少一句值得截图分享的金句。金句特征：短、有力、有转折、有洞察。
- **情绪曲线**：不要平铺直叙。要有起伏——平静 → 冲击 → 反思 → 释然（或反转）。

### 五、封面高亮关键词

- **必须在正文末尾单独一行输出**，格式为：`**封面高亮关键词**: 关键词1, 关键词2`
- 这些关键词必须来自标题中实际出现的词，选 1-2 个最有冲击力的。

### 六、禁用清单（AI 腔黑名单）

以下表达**绝对禁止**出现：
- 开头禁用："在当今数字化时代…""随着 AI 技术的快速发展…""近年来…"
- 过渡禁用："让我们一起来看看""接下来我们来看看""下面我们来聊聊"
- 结尾禁用："让我们一起期待…""未来已来""让我们拭目以待"
- 套话禁用："值得一提的是""需要注意的是""总而言之""综上所述"
- 形容词禁用："令人惊叹的""不可思议的""颠覆性的""革命性的"
- **句式禁用**："不是xxxx，而是xxxxx"——这种句式绝对禁止出现在任何文章中

### 七、新闻类文章硬性约束

当文章内容属于**新闻报道类**（AIHOT新闻、行业动态、产品发布报道等）时，额外强制以下规则：

1. **风格严谨克制**：新闻稿必须以客观事实为主，语气专业、信息准确，不可像普通文章那样随意发挥、碎碎念、情绪化表达
2. **事实优先，评论为辅**：新闻报道中，个人评论/主观感悟/情绪碎碎念的篇幅**严禁超过新闻事实本身的篇幅**。事实占主体（至少 70%），评论点缀即可（最多 30%）。比例失衡会让文章失去新闻稿的专业感
3. **数据支撑**：观点必须有对应的数据、来源或事实依据支撑，不能空口说"很强""很好"
4. **信息来源标注**：关键事实应标注来源（如"据智谱官网介绍""根据 Artificial Analysis 榜单数据"），增强可信度

**普通文章不受此约束**——只有新闻类内容需要额外遵守这些规则。
